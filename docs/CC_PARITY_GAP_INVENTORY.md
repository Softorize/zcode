Comparison of the reference (`~/Downloads/claude-code-main/`, TypeScript + React/Ink) against
this Zig reimplementation (zcode). Produced as the input artifact for a single mega-PRD.

> **Status: first-pass survey.** Generated by parallel exploration agents. Treat every
> specific claim (exact tool name strings, exact reference command names, "reference has X")

## Highest-impact gaps (the real work)

1. **Hooks** — reference has ~27 lifecycle events with a JSON stdin/stdout contract, matcher
   syntax, and 5 hook types (command/prompt/http/agent/callback). We have 3 events over env vars.
   This is the single biggest behavioral gap. (L)
2. **Permissions & sandbox** — reference is a rule engine (allow/deny/ask by `Tool(pattern)`,
   layered settings precedence, session memory, plan-mode gating, OS sandbox). We have hardcoded
   risk tiers and coarse sandbox profiles. (L)
3. **Agent-loop mechanics** — reactive compaction on 413, fallback-model-on-overload, token/task
   budget auto-continuation, tool-use-summary generation, exponential backoff, mid-turn queued
   input. Prompt assembly parity is already done; these loop behaviors are not. (L)
4. **UI/UX fullscreen overlays** — data models largely exist; the rendering layer for plan UI,
   task panel, global search, quick-open, transcript pager, statusline cost/context is partial. (L)
5. **Plugin marketplace backend** — command skeleton exists; install/fetch/update + plugins
   providing MCP servers/hooks is missing. (M)
6. **MCP depth** — SSE transport, settings-scoped config, real elicitation, output limits,
   prompts-as-slash-commands, ToolSearch gating. (M/L)
7. **Memory** — `@import` in memory files, auto-extracted MEMORY.md, `--add-dir`, freshness
   caveat injection. (M)
8. **Sessions** — rewind picker, resume fuzzy search, auto-compaction, markdown export. (M/L)

  dispatcher treats each as unrecognized (identical to any non-existent command), short-circuiting

  or call them: `TaskRun`, `TaskPoll`, `TodoRead`, `Move`, `Copy`, `Delete`, `ListDir`, `Stat`,
  `RunTests`, `OpenPR`, `HttpRequest`, `JsonQuery`.

This was done as a guard + schema-entry removal rather than ripping out ~25 scattered/shared/

single most reviewable form (two explicit lists) — exactly the "reviewable, vetoable" outcome the
removal decision called for. The now-unreachable handler/impl code behind the guard is dead and can

## Hooks

Reference: ~27 lifecycle events with a rich JSON contract; we support 3 over env vars. This is the largest single behavioral gap.

Reference events (trigger / blocking): PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest, PermissionDenied, SessionStart, SessionEnd, UserPromptSubmit, Stop, StopFailure, PreCompact, PostCompact, SubagentStart, SubagentStop, TeammateIdle, TaskCreated, TaskCompleted, Setup, ConfigChange, InstructionsLoaded, CwdChanged, FileChanged, WorktreeCreate, WorktreeRemove, Notification, Elicitation, ElicitationResult.

Reference hook types: `command` (shell, with `if`/`timeout`/`statusMessage`/`once`/`async`/`asyncRewake`), `prompt` (LLM eval), `http` (POST JSON, env-interpolated headers + allowedEnvVars), `agent` (verifier subagent), `callback` (internal, non-persistent).

Contract: matcher uses permission-rule syntax (`Bash(git *)`), JSON stdin in / `hookSpecificOutput` JSON out, exit codes 0=ok / 2=blocking-error-to-model / other=user-error. `CLAUDE_ENV_FILE` for env exports across tools; `watchPaths` output; settings.json `hooks` map keyed by event with matcher+hooks arrays.

Ours today: `pre_tool_use`/`post_tool_use`/`post_tool_use_failure`, file-based discovery (`~/.zcode/hooks/`, `.zcode/hooks/`), env-var I/O, any-nonzero-exit blocks, no matcher, no settings.json, no async, shell-only.

Gaps: all remaining events (L); settings.json hooks config (M); matcher syntax via permission engine (M); JSON I/O contract (M); exit-code-2 blocking semantics (S); prompt/http/agent hook types (M each, agent L); async/asyncRewake (M); timeout/statusMessage/once (S); CLAUDE_ENV_FILE + watchPaths (S); callback hooks for plugin/skill API (M).
