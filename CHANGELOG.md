# Changelog

All notable changes to `zcode` should be documented in this file.

## Unreleased

- Tools/agents leftover fixes (r3b-tools-leftovers fixer pass):
  - The system prompt now includes a genuine `**Available commands (N in this build):**` section (commands-38), generated from the live built-in `/help` command registry via the reference's exact filter/format algorithm (`core/command_list_format.zig`, previously a correctly-built but entirely unused module): hidden commands (commands-37) and removed commands are excluded, surviving entries are deduplicated by name, sorted alphabetically, and rendered as `- /name (aliases: /a, /b): description`. Run `zcode --provider mock --model mock-agent prompt inspect --json` to see it in the rendered `system_prompt`.
  - `zcode --help` and `zcode agents` (no subcommand) no longer name "Claude Code" in a few comparative asides explaining zcode's deliberate CLI-flag divergences (`--dangerously-skip-permissions`, `--print`'s missing `-p` alias, `-v`/`-V`, and the `agents` subcommand's different meaning) -- reworded to describe the divergence generically ("other agentic CLIs") instead of naming the reference product, matching the project's identity rule. These were the one remaining spot naming it in genuinely user-visible (not just source-comment) text; a new test (`cli/args.zig`) guards `--help`'s output going forward.
  - Confirmed already fixed on this branch by earlier, unrelated fix passes (no code change needed here): the hidden `--enable-auth-status` flag's `auth_status` SDK message (headless-sdk-missed-185, wired by `wp6-headless-sdk`) and `mcp/client.zig`'s `scopedCwd()` allocator-corruption regression (fixed by `wp1b-commands-new`) -- both verified end-to-end against the built binary, not just re-read from source.
  - Investigated the previously-reported `zig build test` flakiness (a shifting set of unrelated failures across full runs): not reproducible on this branch -- 10 consecutive full `zig build test` runs all report 0 failed. The flakiness appears to have already been resolved by intervening fixer passes (wp8-repl-ux, wp9-bundled-skills, r3a-repl-chrome) merged before this package's worktree was cut.
- Sessions/storage fixes (wp7-sessions-storage fixer pass):
  - `/fork [prompt]` now genuinely matches Claude Code 2.1.261's "copy this conversation into a new background session and keep working here": it starts the forked session as a real detached background process (the same self-registering mechanism `/background` uses), so it shows up in `zcode ps`/the session registry, and a supplied `[prompt]` is answered headlessly by that background process as the fork's next turn -- previously the prompt was only appended to the fork's store as an unanswered turn a human had to `/resume` by hand, and the fork never appeared in `zcode ps` at all. The current REPL's session/history are still completely untouched.
  - `--resume <id> [--fork-session] --print [prompt]` and `--continue --print [prompt]` now answer the queued prompt in one headless shot and exit, instead of always dropping into the interactive REPL (which hung reading stdin for a `--print` caller with no attached terminal) -- `--resume <id> --print "<prompt>"` also used to silently drop the prompt entirely (it was never parsed into `--resume`'s trailing positional). `--fork-session` is resolved before the prompt is answered, so a fork's reply lands on the NEW session and the original's `.jsonl` is never touched. `--output-format json` renders a proper SDK `result` object for this path too; `--output-format stream-json`/`--input-format stream-json` report a clear "not yet supported" error on `--resume`/`--continue` instead of silently emitting the wrong shape.
  - Session metadata (custom title, AI-generated title, tags, coordinator mode, prompt-bar accent color, PR links) is now also stamped onto the session's own `.jsonl` (on its `type:"summary"` records, alongside the existing `gitBranch`/first-prompt fields) every turn, not only into separate sidecar files -- a `.jsonl` copied to another machine (or with its sidecars deleted) no longer silently loses this metadata; sidecars are still preferred when present (so the freshest edit always wins).

Tool-count, queued-count, tip, and stalled-turn spinner variants are unchanged.

These now genuinely filter the primary session's advertised AND dispatchable tool set (`prompt inspect --json`'s `tool_count`/tool list reflects them; a model that somehow calls a filtered-out tool anyway is still refused at dispatch) -- not just parsed into `Config` fields.

  - Add `-w, --worktree[=name]` and `--tmux[=classic]`: creates (or reuses) a git worktree under `<repo>/.zcode-worktrees/<name>` before the session starts and rewrites the effective `cwd` into it; `--tmux` best-effort spawns a detached tmux session there (both `--tmux` and `--tmux=classic` degrade to plain tmux -- no iTerm2-native-panes driver exists in zcode).
  - Add `--session-id <uuid>` (validated), `--system-prompt <text>`/`--system-prompt-file <path>`, and `--safe-mode`. `--system-prompt` now genuinely REPLACES the entire rendered system prompt (none of zcode's default sections survive), distinct from `--append-system-prompt` which layers on top. `--safe-mode` now genuinely disables CLAUDE.md/AGENTS.md/GEMINI.md/ZCODE.md instruction-file content, the skills listing, and MCP scoped-config loading (`.mcp.json`/`~/.claude.json`/enterprise/plugin servers) for the run, and forces the default output style; plugin/hook/custom-command/keybinding gating remains a follow-on.
  - Add `-d, --debug[=filter]` and `--debug-file <path>` (redirects log output to a file; implies `--debug`). The category filter now genuinely restricts which `std.log.scoped(.<category>)` debug-level lines are emitted (`--debug api,hooks` shows only `.api`/`.hooks`-tagged lines; `--debug !file` excludes just `.file`) -- two real call sites (the shared HTTP client's retry trace, and settings.json hook dispatch) are tagged `.api`/`.hooks` respectively as a starting taxonomy; most other debug lines remain untagged (`.default` scope) and are unaffected by an include-only filter.
  - Add `--disable-slash-commands`: now genuinely disables both skill resolution (the model-facing skills listing AND `/skill-name` REPL resolution) and custom `.zcode`/`.claude` `commands/` `/name` resolution for the run, while built-in commands (`/help`, etc.) keep working. Also add `--no-session-persistence` (requires `--print`).
  - Add `--betas <betas...>` (repeatable): reuses the existing `ZCODE_ANTHROPIC_BETA` passthrough so extra `anthropic-beta` header tokens reach every Anthropic request.
  - Add `--chrome`/`--no-chrome` (per-invocation override of `browser_bridge_enabled`), `--fallback-model <model[,model...]>` (`--print` only; first entry overrides `cfg.fallback_model` for the run), `--effort <low|medium|high|xhigh|max>` (`xhigh` degrades to `max`; overrides the startup reasoning-effort level for the run without persisting), and `--autocompact <auto|N[k]>` (100k-1M tokens; overrides `CLAUDE_CODE_AUTO_COMPACT_WINDOW` for the process).

  - Add `--await-initialize` (requires `--input-format stream-json`): now genuinely blocks on the first stdin line, requiring it to be an `initialize` control_request before starting any turn -- EOF, malformed JSON, or a different first message all error out instead of silently proceeding.
  - Add `--permission-prompts <host|none>`: `none` now genuinely means nobody answers a permission prompt with `--print` -- it overrides even a live SDK-host `can_use_tool` relay, so no such control_request is ever emitted and every ask-tier tool call is auto-denied instead (the permission mode still decides everything else, unchanged).
  - Add `--brief`: genuinely gates the (separately-added) `SendUserMessage` tool, which is now hidden from both the advertised tool schemas and the deferred-tools advisory (so a model cannot ToolSearch its way to it either) unless the flag is passed -- default OFF, matching Claude's own "Enable SendUserMessage tool for agent-to-user communication" wording. Distinct from zcode's existing, unrelated `AttachContext` file-attachment tool (formerly named `Brief`).
  - `zcode --help` now documents `--settings`, `--setting-sources`, `--scope`, `--output-style`, and `--permission-prompt-tool`, which the parser already accepted but never listed.
  - Background-session lifecycle now matches the reference: `zcode kill`/`stop <id|pid>` (aliases) SIGTERM the process and mark it `.stopped` WITHOUT deleting its registry entry, so `zcode attach <id|pid>` can reopen the same conversation later; `zcode rm <id|pid>` is the new destructive delete (what `kill` used to do unconditionally).
  - Add `zcode respawn [id] [--all]` (stops background session(s) so they can be restarted on the current binary -- zcode does not persist the original launch command, so it points at `attach`/a fresh `--bg` run rather than guessing a re-invocation), `zcode install [target]` (alias of `update`; a concrete pinned-version target reports "not yet supported" instead of silently installing latest), and `zcode project purge [path] [--dry-run] [--yes]` (deletes a project's `.zcode/` workspace state).
  - Bare `zcode doctor` (no subcommand) is now a general installation health check (config validity, provider/keychain configuration, `.claude/settings*.json` parse validity), distinct from `zcode doctor enterprise`'s managed-policy-specific checks.
  - Add subcommand aliases: `stop` (= `kill`), `plugin` (= `plugins`), `upgrade` (= `update`), and `zcode agents --bg`/`zcode agents ps` (bridge to `zcode ps`'s background-session listing, since Claude Code's own `agents` command manages background sessions while zcode's pre-existing `agents` lists declared sub-agent definitions).
  - Fix three small memory leaks surfaced during live testing of the above: `-w/--worktree` (without an explicit `--cwd`) leaked one `currentPathAlloc` cwd string per launch (plus, separately, the worktree path itself was never freed after `resolveWorkingDirectory` made its own copy); `--agents`/`--betas`/`--effort`-style flags routed through `core/env.zig`'s in-process override map, which is correctly process-lifetime by design but was never torn down at exit; `-d/--debug <filter>`'s new category-filter storage had the same gap.
