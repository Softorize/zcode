# Governance

zcode uses a maintainer-led governance model while the project is pre-1.0.

## Maintainers

- [@gumruyanzh](https://github.com/gumruyanzh) — project lead and final reviewer

Maintainers triage issues, review pull requests, manage releases, moderate
project spaces, and make final decisions about roadmap and compatibility.

## Decisions

Routine decisions are made in issues and pull requests. Significant changes to
public APIs, security boundaries, governance, or compatibility should include a
written proposal with alternatives and migration impact. Maintainers seek rough
consensus, but the project lead makes the final call when consensus is not
possible.

## Becoming a maintainer

Regular contributors may be invited after demonstrating sustained, constructive
participation, sound technical judgment, and reliable review or maintenance
work. Maintainer access may be removed for inactivity, security reasons, or
violations of the Code of Conduct.

## Changes to governance

Governance changes use the normal pull-request process and require approval from
the project lead.
